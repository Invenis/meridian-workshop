State Management

No Vuex or Pinia. State is managed via three module-level composables (singleton refs that persist for the session):

ComposableResponsibilityKey Exports
useFiltersGlobal filter stateselectedPeriod, selectedLocation, selectedCategory, selectedStatus, getCurrentFilters()
useAuthCurrent user, profile, taskscurrentUser, isAuthenticated, logout()
useI18nLocale, currency, translationst(key), currentLocale, setLocale(), translateProductName()

i18n

Custom implementation in useI18n.js. Supports English (en) and Japanese (ja). Locale stored in localStorage. Currency auto-set: USD (en), JPY (ja). Missing keys fall back to English.

6 Request Data Flow

Trace of a typical filter change (user selects "Tokyo" warehouse):

1. USER ACTION
  FilterBar.vue → selectedLocation.value = 'Tokyo' (useFilters ref, reactive)

2. WATCHER FIRES
  watch(selectedLocation, loadData) in view component

3. API CALL
  api.getOrders(getCurrentFilters())
  → GET /api/orders?warehouse=Tokyo via Axios

4. BACKEND FILTER
  apply_filters(orders, warehouse='Tokyo') (in-memory array filter)
  → Pydantic validation → JSON response

5. FRONTEND UPDATE
  orders.value = response.data → Vue re-renders v-for

7 Known Issues & Technical Debt

  • Missing backend endpoints — Tasks & Purchase Orders api.js calls /api/tasks (CRUD) and /api/purchase-orders — neither is implemented in main.py. App.vue will produce 404 errors on mount. The PurchaseOrderModal component is also referenced in Dashboard.vue but does not exist.
  • Backlog view orphaned from router Backlog.vue exists and is complete but is not registered in Vue Router and not linked in navigation. Users cannot reach it.
  • Spending and Demand endpoints ignore filters /api/spending/* and /api/demand have no filter parameters. The UI renders filter controls that silently have no effect on these views. Users may assume the data is filtered when it is not.
  • Reports module defects (R1 scope) Multiple logged defects in Reports.vue: filter wiring incomplete, i18n gaps, data pattern inconsistencies. Full audit required — this is the primary R1 deliverable.
  • purchase_orders.json is empty The data file exists but contains an empty array. No purchase orders can be created (no endpoint) and no existing POs are available.
  • No automated tests No frontend tests. Three backend pytest files exist (test_dashboard.py, test_inventory.py, test_misc_endpoints.py) but coverage is incomplete. R3 addresses this.
  • CORS open in development allow_origins=["*"] — acceptable for development but must be restricted before any production deployment.
