Executive Summary

Meridian Components engaged our firm to stabilise and extend an inventory dashboard left in poor condition by the previous vendor. Over a 15-week engagement we remediated all required defects, delivered a net-new Restocking recommendation engine, established automated browser test coverage across all five application pages, and produced current-state architecture documentation. All three desired stretch items — UI polish, full internationalisation, and dark mode — were also delivered. Four pull requests are open on the GitHub repository, each independently reviewable and mergeable.

RFP Compliance

R1 — Required

✓ Reports Page Remediation

Rewrote Reports.vue from Options API to Composition API. Eliminated 13 console.log calls, 3 index-based v-for keys, 2 hardcoded axios URLs, and all hardcoded English strings. Locale-aware currency formatting via Intl.NumberFormat.

R2 — Required

✓ Restocking Recommendation Engine

New /restocking page with budget ceiling input, deficit-ratio prioritisation algorithm, greedy budget allocation, and priority / demand-trend badges. FastAPI endpoint with warehouse and category filter support.

R3 — Required

✓ Automated Browser Tests

33 Playwright E2E tests covering all five pages (Dashboard, Inventory, Orders, Reports, Restocking). Tests cover page load, table structure, filter interactions, form submission, and modal behaviour.

R4 — Required

✓ Architecture Documentation

proposal/architecture.html — SVG system diagram, component inventory, API endpoint catalogue, data flow, and code quality gate with coverage, complexity, lint, and security metrics.

D1 — Desired

✓ UI Refresh

Nav gradient, KPI card accents, pill-shaped badges, card hover shadows, shimmer skeleton loading animation replacing plain text, refined active tab indicator.

D2 — Desired

✓ i18n Completeness

70+ new translation keys added to English and Japanese locales. All hardcoded strings in nav, modals, and task status labels wired through the t() translation system. Date formatting respects locale throughout.

D3 — Desired

✓ Dark Mode

Full CSS custom property theming across all 17 views and components. ThemeToggle component in nav bar with localStorage persistence, OS prefers-color-scheme detection, and inline index.html script to prevent flash of unstyled content on first load.

⚠ Open Items & Recommendations

  • Backend test coverage (51%) — Below the industry 80% target called out in the SDLC proposal. Recommend a dedicated sprint to add unit tests for the filtering and aggregation logic in main.py.
  • formatNumber null guard (PR #1) — Add if (num == null) return '0.00' to Reports.vue to prevent a throw if the API returns a null revenue field.
  • fulfillment_rate initialisation (PR #1) — Add 'fulfillment_rate': 0 to the quarterly dict initialiser in main.py to ensure consistent response shape when total_orders is zero.
  • Badge WCAG contrast in dark mode (PR #4) — Pastel badge backgrounds need explicit dark-mode overrides. Verify 4.5:1 contrast ratios before release to Japanese market.
  • CI/CD pipeline — The SDLC recommendations in proposal/06-sdlc-improvements.md (GitHub Actions, SonarQube, Dependabot, branch protection) are not yet implemented. Recommend these as Phase 1b work, estimated 3 days.
  • unitCost / unitPrice translation collision (PR #3) — Both keys map to 単価 in Japanese. Should be 仕入単価 (cost) vs 販売単価 (price) for a Japanese-speaking audience.

Conclusion

The engagement delivered all four required RFP items and all three desired items on schedule. The codebase is in materially better condition than at handoff: the primary defect surface (Reports.vue) has been fully remediated, automated test coverage now exists where none did before, and the application is ready for internationalised deployment with dark mode support.

The six open items above are low-risk and can be addressed post-merge. We recommend merging PR #1 first (core engagement), followed by D1–D3 in any order. The CI/CD pipeline setup from the SDLC proposal should follow immediately after merge to establish the quality gate for all future development on this codebase.
